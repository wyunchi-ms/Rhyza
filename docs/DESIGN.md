# 设计原则

[文档地图](README.md) · [产品记忆与设计原则](product-memory-and-design-principles.md) · [使用指南](user-guide.md)

本页是项目级视觉与交互规则的入口。已确认的分支、引用、知识对象和预览语义以[产品记忆与设计原则](product-memory-and-design-principles.md)为准；[功能矩阵](features.md)说明当前实现程度，设计材料不代表已实现。

## 整体理念

Rhyza 的 UI 是一个克制、可读、不中断思考的 AI 知识工作台，而不只是聊天窗口。视觉克制、信息清楚、交互连续、状态可信，让用户把注意力留给思考，而不是管理界面。

- 内容优先：用排版、间距和层级组织信息，界面不通过装饰抢夺注意力。
- 围绕思考路径：让用户理解问题的来路、分支的关系和知识的来源，而不只是浏览消息流水线。
- 尊重阅读：后台执行、新分支和辅助面板不能擅自改变当前阅读位置或丢失交互状态。
- 渐进呈现：常用路径直接，高级能力和辅助信息按需展开；预览负责快速确认，展开后再提供完整探索能力。
- 状态诚实：加载、完成、异常、禁用、无权限和空状态分别表达；错误有说明，失败有恢复路径。
- 未采集的用量显示“未记录”，不能以 `0` 代替；估算值需标明估算。执行中、知识整理中、失败、中断和带警告完成分别表达，不能把辅助步骤异常说成整轮成功。

以下是设计与评审标准，不代表所有现有控件已经满足；具体能力仍以功能矩阵和实现为准。

## 视觉语言

- 工作台优先：中性表面、可辨认的分隔、克制的青绿色强调；不要在单个页面发明新的主题系统。
- 浅色、深色、高对比度与减少动画应使用同一语义变量体系。变量在 `src/theme.css`，公共外壳在 `src/interface.css`，页面布局在 `src/pages/`。
- 图标统一使用 Lucide/SVG，不以 emoji 代替功能图标。控件共享尺寸节奏、圆角、间距和语义颜色；文字不能依赖低对比度浅灰。
- hover、按下、focus-visible、disabled 与提交中有可辨认且一致的反馈。键盘焦点不能仅依赖 hover；浅色、深色和高对比度主题均需保持可读。
- 动画只服务状态转换和反馈，通常控制在 150–300ms，并尊重减少动画偏好；不通过 hover 缩放或边框尺寸变化造成布局跳动。
- MCP 禁用服务器使用整卡灰底，项目配置的已信任与未信任状态分别使用青绿与警告表面。工具列表在同一窗口断点保持等高，长名称省略并保留完整提示，描述通过信息按钮按需展开浮层，不撑高行或选择器。服务器只读声明的 true、false 及危险声明使用不同语义徽标，但不改变实际权限；权限仍须单独批准。
- 阅读区沿用工作台无衬线字体，并提供明确的中文无衬线回退；正文强调及标题使用克制的半粗字重。原生折叠分组标题使用中等字重，嵌套的 `<b>` / `<strong>` 不再叠加加粗。回答容器和折叠标题保留独立内边距，选中或定位时不改变几何尺寸。

## 通用控件原则

控件应熟悉但不粗糙、紧凑但不拥挤、明确但不喧闹。一致性意味着相同语义有相同表现，不要求所有场景使用相同尺寸。

### 按钮

- 视觉强度与操作重要程度匹配：主要操作使用强调色，次要操作使用中性描边或轻背景，辅助操作使用文字或图标；避免多个同等醒目的按钮争抢注意力。
- 文案直接表达动作，避免含糊的“确定”或“操作”。图标按钮适用于含义明确、空间紧凑的场景，并提供本地化悬停提示和无障碍名称。设置页的连接刷新、登录／退出、软件包安装／浏览以及列表内快捷操作使用独立 icon button，尺寸与间距一致，不混用大块文字按钮。聊天消息底部的重试与编辑后重试同样使用图标，与复制、分支对齐；主要表单提交、页面错误恢复和确认操作仍使用明确文字。
- 危险或难以撤销的操作不能只靠图标表达后果。目标明确的列表行可用带提示和无障碍名称的移除图标作为入口，但确认层必须说明目标、影响范围并使用文字按钮。
- 禁用时说明原因，提交中明确显示进度或等待状态并防止重复执行；不能只改变颜色而让用户猜测。

### 列表

- 优先保证扫描效率：主标题、辅助描述、状态和操作各有稳定位置，通过字号、字重和间距形成层级，不把所有信息做成同等醒目的标签。
- 行高与留白匹配内容密度，既不拥挤，也不为装饰过度稀疏。分组优先使用标题和留白，必要时增加分隔线，不给每行叠加重边框。
- 图标应提供辨识信息，不为同类选项重复添加同一个图标。模型列表直接显示名称与紧凑的上下文／推理说明，仅当前项显示勾选；鼠标悬停不触发自动滚动，只有打开列表和键盘导航时才确保目标可见。列表内部滚动不反复重算浮层位置，也不带动背景阅读区。
- hover 表示可操作，选中表示当前对象，键盘焦点表示操作目标，三者分别表达；多选状态可使用更强强调，但不与对象自身状态混淆。
- 列表和目录的选中态使用整块强调背景与完整细边框，不使用单侧标线或括号式装饰。对话列表的当前阅读节点使用整块高亮，摘要多选保留更强的实色强调；聊天定位使用整块浅底与完整轮廓。树结构连线、引用和错误提示的侧边线不属于选中态，应保留。
- 回答目录在可用留白充足时可扩展至约 320px，提升标题可读性；宽度仍受正文前方实际间距限制，不挤压回答，窄窗口留白不足时隐藏。
- 空集合、搜索无结果和加载失败使用不同文案与后续动作，不以同一个空状态代替。
- 软件包列表把 scope 与安装状态分成独立文字标签：用户／工作区使用中性色，已安装使用成功色，磁盘缺失使用警告色；语义颜色随主题变化，不能只显示颜色或把安装状态推断成启用、连接或受信任状态。

### 输入框与表单

- 文本输入与多行输入使用柔和的中性色表面，不加硬描边；焦点以强调色底线提示，错误以危险色底线提示。标签说明填写内容，辅助文字解释限制，placeholder 仅提供示例，不能代替标签。选择器、复选框、单选框和带独立外层容器的搜索框保留各自的交互表面。
- 表单中的 `Select.field` 与文本输入保持同宽、同高；纵向表单的标签在控件上方，设置页则遵循已有双列／窄屏单列布局。布局宽度必须覆盖控件外层，不只覆盖内部按钮；标签文字样式不能误作用于选择器外层。工具栏保留紧凑选择器及显式宽度，不全局改为整行布局。
- 聊天输入使用单一外壳，文本编辑区不再嵌套描边、焦点阴影或独立背景；焦点反馈由外壳承担。内容与底部操作之间预留一行文字的空间，随换行自动增高，到高度上限后在编辑区内部滚动，不能把工具栏推离视口。
- 校验错误贴近对应字段，说明原因与修正方式，不只将边框染红。保存失败保留输入，不能要求用户重新填写。
- 后台刷新同一知识对象时保留正在编辑的草稿；提交只合并用户编辑的字段，不用旧快照覆盖最新连接与来源。图表保存先校验语法，保存和导出异常都要提供可见反馈。
- 区分禁用与只读：禁用表示当前不可操作，只读内容仍可阅读与复制。

### 下拉框、复选框与开关

- 形式匹配选择语义：单选用于互斥选项，复选用于可组合选项，开关用于明确的开启／关闭状态；不为视觉偏好替换控件语义。
- 下拉选择使用共享 `Select`，仅在图标能区分选项时保留前置图标，当前项显示勾选；使用主题表面、完整选中背景及键盘焦点，支持方向键、首尾键、输入检索、Enter 选择和 Escape 关闭。弹窗内的列表保留在同一模态层，不能被滚动容器裁切或落到遮罩后。
- 输入框底部使用小型、无前置图标的胶囊控件。模型和思考强度合并为一个入口：一级菜单显示当前模型与强度档位，再展开二级模型列表。强度使用中性、绿、青绿和琥珀色区分关闭／低／中／高，文字与选中轮廓始终保留；这些颜色表示推理档位，不表示成功或警告状态，也不暗示 Provider 必定支持该档位。
- 开关标签说明开启的功能，状态不能只靠颜色表达；不要让用户猜测亮起代表什么。

### 卡片与容器

- 卡片用于聚合独立对象或一组相关信息，不是所有内容的默认包装。能通过对齐、留白和分隔表达结构时，不再增加容器。
- 背景、细边框和轻阴影各有用途，不为制造层次同时堆叠。圆角与间距保持统一，避免卡片套卡片和层层描边。
- 容器负责组织内容，不替内容制造存在感；辅助操作与状态不能压过主体信息。

### 菜单与提示

- 菜单靠近触发位置，相关动作分组，危险动作与常规动作分开；选项命名简洁明确，复用同一套菜单视觉和键盘行为。
- 点击外部或按 Escape 可靠关闭菜单；依附选区的菜单在选区消失后关闭。浮层不能遮挡关键操作、超出可用区域或造成不必要的滚动。
- Tooltip 用于补充说明，不承载完成任务必需的信息。对含义不明确的动作或关键操作限制提供可见标签或说明，不能要求用户必须悬停才能理解。
- 上下文用量环通过悬停或键盘聚焦显示轻量提示，不抢焦点、不放关闭按钮或重复说明；移出后关闭，Escape 可直接收起，触屏保留点击入口。提示根据实测尺寸紧贴用量环上方，通常间隔 8px，靠近视口边缘时约束位置。
- 回合用量图标通过悬停或键盘聚焦显示完整用量面板，面板使用品牌浅底与独立指标卡提升和正文的区分度，省略重复标题，并固定在视口右侧；根据触发图标所在的上下位置选择右上角或右下角，避免始终落在阅读区域中部。位置受视口约束，不遮罩或锁定背景。鼠标可移入面板查看内容，移开后关闭，Escape 收起，触屏可点击切换。

### 弹窗

- 只在需要确认或集中完成任务时打断用户，不把普通反馈都变成弹窗。标题说明任务，正文解释必要信息和后果，底部操作主次分明。
- 确认操作使用应用内模态弹窗，不调用系统 `window.confirm`。标题、操作图标、说明和底部按钮有统一层级；删除操作使用危险色，初始焦点落在取消按钮，Escape 取消并恢复触发控件焦点，提交中不允许重复操作或关闭。
- 危险操作明确说明目标与影响范围，区分移除注册、删除文件等不同后果，不能只问“确定删除吗”。
- 表单弹窗失败后保留草稿与错误，允许修正或重试；模态弹窗约束焦点，关闭后恢复触发位置。
- 真正的模态使用原生 `dialog.showModal()`，使背景不可交互；嵌套预览的 Escape 只关闭最上层。普通菜单与信息浮层不冒充模态，使用实测尺寸限制视口边界，并提供键盘关闭与焦点恢复。

## 交互边界

- 从历史回答追问、选择引用与查看知识是连续的阅读流程；不能因提交新分支而抢走当前阅读位置。
- 选区 Explain／追问是独立发送，不清空普通输入框的草稿，也不携带其中尚未发送的图片。失败或中断后，Retry 复用原用户与回答回合，只显示本次重试的回答；Edit and retry 在确认替换草稿后更新原问题、附件和引用，不额外插入一轮重复对话。
- 减少动画同时约束 CSS 和显式 JavaScript 滚动；用户或系统启用该偏好时，定位使用即时滚动。图路径使用静态主题强调色，不添加持续流动的装饰渐变。
- 设置页隐藏工作区侧边栏，左侧是设置分类，右侧只显示选中的分区；窄窗口改为可横向浏览的分类栏。返回应用不改变原工作区侧边栏的开关状态。
- 设置分类的分组标题使用更小、更粗的辅助文字，组间用留白和分隔线区分；分类项保持独立缩进。选中项在宽、窄布局中都使用整块强调背景、完整细边框和加粗文字，不使用左侧括号或底部指示线；键盘焦点另用 focus-visible 轮廓标识。
- 工作区底部快捷入口属于工作区侧边栏，侧边栏收起时一起隐藏。
- Workspace 页面管理当前工作目录；当前工作区卡片仅显示标题、目录路径和切换入口，错误仍就地展示。Sources 是页面内的资料源子区块，不重复显示索引状态汇总；每条资料源保留自身状态。Add sources 使用标题行右侧的加号图标按钮，保留本地化提示和无障碍名称，空列表和非空列表共用此入口，不放在页面顶栏。
- `HashRouter` 的 hash 用于路由，设置分区不能使用会覆盖路由的裸 `#heading` 链接。

变更这些规则时，同时更新相关的 UI 测试、[使用指南](user-guide.md)和[功能状态](features.md)（若能力发生变化）。
