[00:00—00:30] 让对话跟得上发散的思路
现在很多 AI Chat，主要还是一问一答，沿着一条线往下聊。
但思考经常会发散：这个概念是什么？换个方案呢？另一个方向又怎样？
有些工具也能分支，但来回探索、保留关系、回到主线，往往还不够顺手。
这就是我做 Rhyza 的出发点：让对话跟得上发散的思路。

[00:30—00:36] 一个项目，一个工作区
这次拿 Rhyza 自己的源码演示。先选好项目工作区。

[00:36—00:42] 添加源码和文档
把源码加到 Sources，就能搜索和读取相关片段。

[00:42—00:54] 准备一篇有层次的回答
先问清楚一条消息在系统里怎么流转。
这是一条主线。接下来，我们从其中的问题展开几个不同方向，再随时回到这里。

[00:54—01:02] 在阅读途中发现一个疑问
一条主线里，常常藏着值得展开的新问题。
这里我先从一个不懂的概念分出去。

[01:02—01:18] Explain：先创建解释节点
选中它，点 Explain，就能直接请求解释。
新的问题会提交，但不会把我带离正在读的这段内容。
解释在旁边生成，我可以继续读下去。

[01:18—01:34] Ask：把自己的问题放进支线
如果有更具体的问题，就用 Ask about this。
例如这里换成消息队列会怎样？
把问题发出去，当前阅读路径仍然保持不变。

[01:34—01:46] 新回答完成，也不抢走阅读位置
就算支线回答已经生成，也不会把阅读视角抢过去。
我可以先把这一节看完，再决定要不要展开研究。

[01:46—01:58] 看完这一段，再回头看支线
读完这一段，再去看刚才展开的不同方向。
每条探索路径都保留下来，也随时能回到主线。

[01:58—02:12] Node View：展开每一轮探索
Node View 把每一轮探索展开成节点。
哪一轮接着哪一轮，在哪里分出新的方向，都能顺着连线看到。

[02:12—02:36] List View：把没有分叉的一段收成一项
切到 List View，侧栏会紧凑很多。
比如同一会话里连续问了 A、B、C，中间没有分叉，就合成一个列表项。
到了分叉的地方，新的方向仍然分开保留。
压缩的是列表里的显示，完整聊天内容都还在。

[02:36—02:50] 看全貌用节点，日常阅读用列表
节点图帮我看清发散之后的路径和关系。
列表把连续的讨论收紧，方便日常阅读。
两种视图，看的都是同一组探索。

[02:50—03:00] 给探索进度做标记
研究完的支线，我标成 Completed。
还没看完的，就标成待探索或进行中。

[03:00—03:16] 只留下现在还要看的路径
然后用筛选，只显示待探索和进行中的路径。
已完成的末端支线就先从视图里隐藏了。
屏幕上留下现在要看的内容，界面清爽，也更容易集中注意力。

[03:16—03:26] 隐藏不是删除，随时恢复
筛选在两种视图之间也保持一致。
想回顾时恢复全部状态，之前的节点都还在。

[03:26—03:40] Outline：先看到回答的结构
长回答还有一个很实用的优化：Markdown 目录。
先看标题层级，就知道这篇回答讲了哪些部分。
不用一路滚到底才发现重点。

[03:40—03:54] 点目录，直接到关心的部分
我想先看请求调度，就直接点这一节。
正文跳到对应位置，目录也会标出正在阅读的章节。
在长回答里找内容会方便很多。

[03:54—04:06] 读过的章节折叠，需要时再展开
读过的部分可以先折叠起来。
从目录再点回去，会展开需要的章节。
长回答就可以按自己的节奏来读。

[04:06—04:18] 让结论变成可复用的知识
发散探索之后，有用的结论还可以整理进 Knowledge。
把稳定的概念、关系和流程图留下来，供下一次探索使用。

[04:18—04:32] 概念和图表留在同一个工作区
概念和模块保存为 Entity，流程可以保存为 Diagram。
它们属于这个工作区，后面的对话还能继续用。

[04:32—04:46] 悬停下划线，先看概念摘要
阅读时，你会看到一些带下划线的名称。
当它关联到知识库里的概念，悬停就能先看摘要。
需要了解更多，再点开查看详情。

[04:46—05:00] 图表也能从正文直接打开
图表名称也能这样用：悬停先看说明，点击再打开图。
查完关掉预览，就可以接着读这篇回答。
知识库里的内容，会在用到的时候重新出现。

[05:00—05:14] 新问题继续引用已有结论
如果要继续研究，还可以用 @ 把这些知识带进新问题。
前面的探索，就成了后面思考的起点。

[05:14—05:28] 只做一个范围明确的修改
需要动手时，也能让 Agent 做一个范围明确的小修改。
比如只给 README 补一段刚才梳理出的流程说明。

[05:28—05:42] 确认路径，检查 Diff
修改后先确认当前目录和隔离标记，再看 Diff。
检查没问题，也可以导出 patch，留给后续处理。

[05:42—05:56] 选择 Provider 和模型
Rhyza 目前可以接入 Copilot、Codex、Claude Code 和 Azure OpenAI。
根据自己的账号和服务选择模型，具体能力和用量取决于 Provider。

[05:56—06:06] 调整阅读外观
主题和字体大小，也可以按阅读习惯调整。
会话与知识保存在本地；调用 AI 时，相关内容会发给所选服务。

[06:06—06:20] 让对话跟随思考展开
Rhyza 最初想解决的，就是线性聊天难以承接发散思考的问题。
让每个方向都能展开，也能随时回到主线。
