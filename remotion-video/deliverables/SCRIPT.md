核心叙事：线性聊天难以承接发散思考。Rhyza 的出发点是让多个方向自由展开、保留探索路径，并随时回到主线。全程使用公开的 Rhyza 演示副本，通过 Explain / Ask、两种视图、标记筛选和 Markdown 目录展示具体体验；Knowledge 收束结论，再通过正文里的知识链接展示复用。代码修改和 Provider 设置只简要带过。

录制前准备：连接一个可用 Provider；准备同一 Session 连续四轮问答 A、B、C、D，其中 C 为带分级标题的长回答。从历史 C 新建 Explain 支线 E、Ask 支线 F，原后续 D 保留。提前准备一个已保存的 Entity 和 Mermaid Diagram，并确认回答正文中的名称已经匹配为知识链接。

交互口径：按钮名为 Explain 和 Ask about this；List View 合并同一会话内没有分叉的连续路径，不删除或改写聊天内容。筛选选择要显示的叶节点状态，并保留命中节点的祖先路径。知识链接悬停显示摘要，点击打开详情或完整图表。

录屏建议：1920×1080、30fps、隐藏系统通知，应用字体放大到成片可读。每个动作前后留 2 秒余量；将等待剪短，但保留真实点击和 2—3 秒流式输出。配音独立录制，录屏原声默认静音。

## 00:00—00:30 · 让对话跟得上发散的思路

### 00:00—00:30 · 让对话跟得上发散的思路

画面：先展示线性的一问一答，约第 7 秒展开成多个探索方向；主标题为“思考会发散，对话也应该”。这是概念示意，不冒充实机操作。

旁白：

> 现在很多 AI Chat，主要还是一问一答，沿着一条线往下聊。
> 但思考经常会发散：这个概念是什么？换个方案呢？另一个方向又怎样？
> 有些工具也能分支，但来回探索、保留关系、回到主线，往往还不够顺手。
> 这就是我做 Rhyza 的出发点：让对话跟得上发散的思路。

## 01:58—02:50 · 同一条思路，两种看法

### 01:58—02:12 · Node View：展开每一轮探索

录屏文件：`public/recordings/09-node-view.mp4`（成片段落 14 秒）

操作：切换 Node view，展示同一会话 A → B → C，以及从 C 延伸的原后续 D、解释 E 和追问 F。鼠标依次经过 A、B、C 和分叉点。

拍摄提示：A、B、C 为剪辑标注，不需要改应用标题。准备真实连续三轮，保证同一 Session；图上展示真实节点。

旁白：

> Node View 把每一轮探索展开成节点。
> 哪一轮接着哪一轮，在哪里分出新的方向，都能顺着连线看到。

### 02:12—02:36 · List View：把没有分叉的一段收成一项

录屏文件：`public/recordings/10-list-compression.mp4`（成片段落 24 秒）

操作：在同一组对话上切换到 List view，展示 A、B、C 对应的单个列表项，以及 D、E、F 三条后续路径。停留时配合下方结构示意。

拍摄提示：仅同一 Session 内的单子节点连续路径会合并；会话边界保持可选。讲清这是显示压缩，不是删除、摘要改写或模型上下文压缩。

旁白：

> 切到 List View，侧栏会紧凑很多。
> 比如同一会话里连续问了 A、B、C，中间没有分叉，就合成一个列表项。
> 到了分叉的地方，新的方向仍然分开保留。
> 压缩的是列表里的显示，完整聊天内容都还在。

### 02:36—02:50 · 看全貌用节点，日常阅读用列表

录屏文件：`public/recordings/11-switch-views.mp4`（成片段落 14 秒）

拍摄提示：不把列表折叠按钮当作路径压缩；通过同一数据的两种视图证明含义。

旁白：

> 节点图帮我看清发散之后的路径和关系。
> 列表把连续的讨论收紧，方便日常阅读。
> 两种视图，看的都是同一组探索。
